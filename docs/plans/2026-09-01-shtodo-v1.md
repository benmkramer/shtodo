# shtodo Version One Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the first usable shtodo release as a fast, persistent, keyboard-first terminal todo application.

**Architecture:** A thin binary calls a synchronous library runtime. Crossterm events map through a declarative binding table to semantic actions, pure application and task state apply those actions, a versioned JSON store persists committed mutations, and Ratatui renders borrowed state.

**Tech Stack:** Rust 2024, Rust 1.89.0 or newer, Ratatui 0.30.2, Crossterm 0.29.0, color-eyre 0.6.5, Serde, serde_json, and tempfile for tests.

**Spec:** `docs/specs/2026-09-01-shtodo-v1-design.md`

## Global Constraints

- Rust edition is 2024 and the minimum supported Rust version is 1.89.0.
- Primary runtime targets are macOS and Linux; keep Windows build-compatible where practical.
- Keep the event loop synchronous and blocking. Do not add threads, timers, channels, polling, or an async runtime.
- Keep `main.rs` thin and keep task/application logic independent from Crossterm, Ratatui, and filesystem APIs.
- Use explicit `Mode` and `Action` enums, borrowing where ownership is unnecessary, and `Result` for fallible operations.
- Production code must not use `unwrap`, `expect`, or panic-based recovery.
- Do not introduce traits, dependency injection, generic frameworks, a database, Clap, a configuration parser, or speculative extension infrastructure.
- Persist every committed mutation immediately through a versioned JSON snapshot and an exclusive per-scope standard-library file lock.
- Global scope is the default. `--local` uses the exact canonical current working directory and never searches for a Git root.
- Completion remains in place. Deletion is soft. `u` restores the latest deletion across restarts. `J` and `K` reorder visible tasks.
- User-editable keybindings, trash, sidebar, themes, plugins, sync, reminders, packaged binaries, and package-manager distribution are out of scope.
- Commit only after the task's focused tests and `cargo fmt --check` pass.
- Final verification commands are exactly:

```bash
cargo fmt --check
cargo clippy --all-targets --all-features --locked -- -D warnings
cargo test --locked
```

```rust
use std::{error::Error, ffi::OsString, fmt};

#[derive(Clone, Copy, Debug, Eq, PartialEq)]
pub(crate) enum ScopeChoice { Global, Local }

#[derive(Clone, Copy, Debug, Eq, PartialEq)]
pub(crate) enum Command { Run(ScopeChoice), Help, Version }

#[derive(Debug, Eq, PartialEq)]
pub(crate) struct CliError { argument: OsString }

impl fmt::Display for CliError {
    fn fmt(&self, formatter: &mut fmt::Formatter<'_>) -> fmt::Result {
        write!(
            formatter,
            "unsupported shtodo arguments: {:?}\n\n{}",
            self.argument,
            usage()
        )
    }
}

impl Error for CliError {}

pub(crate) fn parse_args<I>(args: I) -> Result<Command, CliError>
where
    I: IntoIterator<Item = OsString>,
{
    let values: Vec<OsString> = args.into_iter().collect();
    match values.as_slice() {
        [] => Ok(Command::Run(ScopeChoice::Global)),
        [value] if value == "--local" => Ok(Command::Run(ScopeChoice::Local)),
        [value] if value == "--help" || value == "-h" => Ok(Command::Help),
        [value] if value == "--version" || value == "-V" => Ok(Command::Version),
        [value, ..] => Err(CliError { argument: value.clone() }),
    }
}

pub(crate) fn usage() -> &'static str {
    "Usage:\n  shtodo\n  shtodo --local\n  shtodo --help\n  shtodo --version\n"
}
```

- [ ] **Step 3: Implement fallible terminal setup and restoration**

Use Ratatui 0.30.2's fallible APIs:

```rust
struct TerminalGuard {
    terminal: ratatui::DefaultTerminal,
    restored: bool,
}

impl TerminalGuard {
    fn init() -> std::io::Result<Self> {
        match ratatui::try_init() {
            Ok(terminal) => Ok(Self { terminal, restored: false }),
            Err(error) => {
                ratatui::restore();
                Err(error)
            }
        }
    }

    fn restore(&mut self) -> std::io::Result<()> {
        ratatui::try_restore()?;
        self.restored = true;
        Ok(())
    }
}

impl Drop for TerminalGuard {
    fn drop(&mut self) {
        if !self.restored {
            ratatui::restore();
        }
    }
}
```

The loop draws first, blocks on `crossterm::event::read()`, maps Key events through `input::map_key`, applies the action, saves only on `Persisted`, and breaks on `Quit`. Resize and non-key events return no action and cause a redraw on the next iteration. Call the fallible explicit restore after loop success. Use `WrapErr` at draw/read/save/restore boundaries.

```rust
/// Runs shtodo using process arguments and local environment state.
///
/// # Errors
///
/// Returns an error when arguments, storage, terminal setup, input, rendering,
/// persistence, or terminal restoration fails.
pub fn run() -> color_eyre::Result<()> {
    match cli::parse_args(std::env::args_os().skip(1))? {
        cli::Command::Help => {
            use std::io::Write as _;
            std::io::stdout().lock().write_all(cli::usage().as_bytes())?;
        }
        cli::Command::Version => {
            use std::io::Write as _;
            writeln!(
                std::io::stdout().lock(),
                "shtodo {}",
                env!("CARGO_PKG_VERSION")
            )?;
        }
        cli::Command::Run(choice) => {
            let home = storage::home_from_environment()?;
            let scope = storage::scope_from_environment(choice)?;
            let store = storage::Store::open(&home, scope)?;
            let app = app::App::new(store.load()?);
            terminal::run(app, &store)?;
        }
    }
    Ok(())
}
```

Do not use `print!` or `println!` because their hidden stdout writes can panic. Unknown arguments propagate before storage or terminal initialization.
